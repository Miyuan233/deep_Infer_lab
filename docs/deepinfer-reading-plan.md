# DeepInfer 学习与迁移边界

## 从现在开始研究什么

DeepInfer 研究与 M1 单卡基线并行，而不是等到 Kernel 开发时才开始。先读[官方 README](https://github.com/deepseek-ai/DeepInfer)和[部署问答](https://github.com/deepseek-ai/DeepInfer/blob/main/doc/inference_deployment_qa.md)，画出“模型计算 → 推理引擎 → 在线服务”的边界，再追踪一个请求如何经过 Prefill、Decode、调度和 KV Cache。阅读产出是自己的架构图、概念表和可验证的问题，不是照搬性能数字。

## 与本项目硬件的关系

截至 2026-10-24，官方 README 列出的 NVIDIA 硬件为 SM100，支持模型为 DeepSeek-V4.1-Flash；本项目 H200 的计算能力为 SM90，拟作为首个基线的 Qwen3-8B 也不在该支持列表。官方公开版提供离线推理核心，但完整在线服务仍需要未包含的 KV Cache 系统、阶段解耦及副本负载均衡组件。因此不能把当前公开版 DeepInfer 直接部署到本项目单卡 H200，并宣称完成端到端对比。

这不妨碍研究其设计思想。是否移植某个单独组件，须逐项核对许可证、硬件架构、模型路径、依赖版本、输入 Shape 和正确性；最后以本项目 vLLM 实际瓶颈为准。若未来上游增加 SM90 支持，应重新核对最新代码，而不能沿用本次结论。

## 建议阅读顺序

1. **系统边界**：从 README 和部署问答区分开源引擎与未开源的服务组件，解释“Kernel 快”与“端到端快”为什么不同。
2. **请求路径**：理解 Prefill、Decode、KV Cache、调度、批处理和异步重叠；用 M1 测得的 TTFT、TPOT、吞吐量对应各环节。
3. **计算热点**：按 M2 的 Profiler 证据选择注意力、矩阵乘、MoE 专家计算或其他目标，再阅读 DeepInfer 对应实现及其依赖项目。
4. **迁移决策**：写出“本机真实瓶颈 → 上游设计依据 → SM90/Qwen 适配工作 → 正确性测试 → 微基准 → vLLM 真实链路验证”的闭环。若没有可行路径，明确记录不采用的原因。

## 立即可做的学习练习

读完官方 README 和部署问答后，用一页中文回答：哪些功能属于公开的离线引擎，哪些是完整在线服务还需要的？为何一台 H200 上的 Qwen3-8B 不适合直接复现 DeepInfer 的多卡数字？这两问能帮助我们避免把“参考架构”误解为“必须完整移植”。

# M1 首次离线加载功能验证（待 GPU 授权）

## 目的与边界

目标只是在获授权的单张 H200 上验证已校验的 DeepSeek-V2-Lite-Chat 能被本机 vLLM 加载，并完成一次少量 Token 的生成。这不是在线服务，也不是 TTFT、TPOT 或吞吐量 Benchmark。失败同样要保存原始错误；不得仅因上游支持列表或权重校验通过就声称本机可运行。

## 资源预算

- 候选设备：仅用户再次明确授权的一个 `nvidia-smi` 编号；当前只读观察 GPU 3 无计算进程、已用 0 MiB，但检查会在执行前重做。
- 模型：`models/DeepSeek-V2-Lite-Chat/` 中固定提交 `d174ca84ff4d8cd51f8e927bcb1242555e31b2c0`，BF16、TP=1。
- vLLM 试验参数：`gpu_memory_utilization=0.45`、`max_model_len=4096`、`max_num_seqs=4`、`enforce_eager=True`。H200 报告总显存 143771 MiB，0.45 对应约 64697 MiB（63.2 GiB）的 vLLM 目标占用；这不是硬性显存上限。为启动和 CUDA 上下文预留空间，计划按约 60–75 GiB 显存预算向用户说明，若运行前设备不空闲或余量不足则中止。
- 时间：最多 15 分钟；只生成一次不超过 32 个输出 Token 的短文本。运行结束要确认本次进程退出和显存释放。
- 网络：只用已下载的本地文件，强制离线；不再下载其他权重。

## 运行前后的核对

1. 核对具体 GPU 编号授权及 UUID，立即重查 `nvidia-smi`，拒绝已有计算进程或未知显存占用。
2. 用设备 UUID 限定 `CUDA_VISIBLE_DEVICES`，确认 PyTorch 只看到一张预期的 H200。
3. 离线加载本地模型并生成少量 Token；记录代码提交、模型修订、Engine 参数、输出 Token 数、错误和总耗时。启动耗时不作为性能结论。
4. 退出后重查设备进程与显存。不得干扰其他用户任务。

当前 vLLM `0.32.0` 帮助命令还提示：FlashInfer 预编译内核不可用，且 `nvcc`/`ninja` 未在预期 PATH。首次加载可能走其他内核路径，也可能暴露编译依赖问题；此处只作为风险记录，不为绕过问题修改系统级 CUDA。若失败，先保存证据、分析原因，再决定是否在隔离环境内修复。
